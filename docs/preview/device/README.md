## 実機での確認

1. SafariでこのURLを開き、判断・銘柄・市場・品質・管理の5タブ、250本の高さと最新側表示を確認。
2. 共有→ホーム画面に追加→「米国確認」で起動。画面上部「実機確認の手順・状態」の起動・SW表示を確認。
3. オンライン読込完了後に通信を切り、確認版を閉じて再起動。保存版表示とGPT転送停止を確認。
4. 通信を戻し、配信版表示への復帰を確認。通常アプリが4タブで、個人記録が残ることを確認。

通常アプリの削除・データ消去は不要。iOSバージョン、Safari/ホーム画面の別、実際の再起動方法と結果を記録する。

## 分離境界と未完了

SW scopeはこのディレクトリのみ。静的資材は `us-stock-device-shell-*`、検証済み公開データは `us-stock-device-delivery-v1` に保存。SW更新は同じ確認版の旧shellだけを削除し、通常キャッシュの移行・削除は行わない。通常アプリのlocalStorage設定は読み書きしない。iframeはallow-scriptsだけのsandbox。

自動検証はChromium上の並行起動・タブを閉じたオフライン再起動・通常記録保全。iPhone/Safari・OSによる終了後の再起動・ストレージ削除等を代替しない。DEVICE_PASS、通常PWA採用、本番切替、Production昇格は未承認。PR #22/#31/#32およびPrivate #44のマージ許可ではない。

再生成：検証済みartifact ZIPを展開し、`node scripts/build-device-preview.cjs <展開先> docs/preview/device`。生成スクリプトは今回のreleaseに固定しており、データ更新には別途レビューが必要。

## 2026-10-15 相談データの鮮度・日時

相談文の要点・全文は `quality_scope: RECORDED_AT_GENERATION` と `freshness` を分けて出力する。保存時PASS・警告0件は元の記録を維持し、相談文作成時の端末時計で基準日からの暦日数を評価する。要点・全文・分割・保存には同じ評価日時を使う。

- `freshness.data_kind`: `FIXED_PREVIEW`。自動の市場データ更新なし。
- 判定は既存の4暦日超。JSTの暦日で評価し、営業日数や予測期間に読み替えない。4暦日以内でも最新価格の保証ではない。
- 無効な時計・基準日、未来の基準日は、それぞれ未確認または未来として出す。
- `status.generated_at_jst`: 市場データの生成日時。
- `delivery_manifest.verified_at`: 配信ファイルの照合日時。市場データの更新日時ではない。
- `freshness.evaluated_at`: 相談文作成時の端末時計による鮮度評価日時。

表示側の詳細にも「データ生成」と「配信ファイル照合」を明記する。変更するSWはdevice専用の静的資材cache名のみ。通常PWAの採用や正式売買資格を変更しない。

## 2026-10-15 版更新時のHTTPキャッシュ対策（PR #40）

PR #39後の追加対策。device専用SWのインストール時は、静的資材を `Request(..., {cache:'reload'})` で取得する。有効期限内の古いHTTPキャッシュが新しいshellへ再保存されることを防ぐ。取得完了後だけ有効化し、途中失敗時は既存の確認版を維持する。通常起動・オフラインでは従来のshellキャッシュを使う。

cache名には資材ハッシュに加えて取得方式の版を含める。scope、取得対象、旧shellの削除範囲、固定配信・通常アプリ・個人記録は変えない。1時間のHTTPキャッシュが残った旧版から新版への更新を自動テストへ追加した。iPhoneでの正式受入とは区別する。

再現記録: commit `81bd550843b9c0505b0491e304d299ed3b7e90d4`、Device Preview Isolation run `38589633859`。SWの更新と再読込後も `update-fixture-old` が残り、新版表示を期待した検査で失敗した。これはテストサーバー上で確認した原因であり、公開ブラウザーの内部キャッシュまで独立確認した記録ではない。修正後の同じテストと公開確認結果はPR #40に記録する。

取得方式の根拠: [MDN Request.cache](https://developer.mozilla.org/en-US/docs/Web/API/Request/cache)。`reload` はHTTPキャッシュを参照せず取得し、その取得結果でHTTPキャッシュを更新する。
